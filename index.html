Instant disposable Windows environments.

WinQuick runs Windows commands, builds, tests and desktop applications from your Mac. Each run starts clean and is discarded when it finishes.

What it does

Use Windows as a local execution target.

Throwaway Windows for any command

Every run gets a clean, real Windows, runs your build, test or tool, hands back stdout, stderr and the exit code, and is discarded. Nothing to maintain, nothing leaks between runs.

winquick run -w . -- dotnet test

Build a project

One command reads the project, picks the toolchain from its shape, installs the .NET capability it needs, restores packages offline, builds in a disposable Windows, and keeps the output. Run any command yourself with winquick run when you need to.

winquick build ./MyApp # -> ./winquick-artifacts

Bring your own tools

It is a real Windows, so it runs more than .NET. Register any toolchain once — a C compiler, Go, Node, Python, a portable CLI — and every run keeps it cached and on PATH, with no re-copy.

winquick tool add go --from ./go winquick run -w . -- go build ./...

Run desktop applications

Launch Windows desktop applications in a headless session, capture screenshots, and drive controls exposed through Microsoft UI Automation. A desktop session needs both capabilities.

winquick capability install dotnet-sdk winquick capability install desktop winquick ui-test ./publish --script smoke.uitest

Each run

How a run works.

  1. 1
    Workspace copied inYour source on the host is not modified.
  2. 2
    Windows runs cleanThe guest has no network access — isolated by design.
  3. 3
    Requested artifacts copied outThe disposable environment is then discarded.

Desktop applications

Run and test Windows desktop applications.

The desktop capability starts a headless Windows desktop. WinQuick can launch Windows applications and capture screenshots of them. Applications that expose controls through Microsoft UI Automation can also be inspected and driven. WPF and WinForms projects can additionally be built inside Windows before being tested.

Fast enough to forget it is a VM

A real Windows command in about a third of a second.

A full Windows VM takes minutes to boot and then sits there eating memory. WinQuick resumes a prepared Windows in ~310 ms, runs your command, and throws the machine away — nothing to boot, nothing to maintain, nothing left behind.

See it work

From your Mac, into a clean Windows, and back.

Build a .NET project, keep the output
$ winquick build ./MyApp -c Release
→ restoring packages offline
→ building in a clean Windows
Build succeeded — kept ./winquick-artifacts/MyApp.dll
Compile a Windows .exe — no Windows in sight
$ winquick tool add go --from ./go
Tool 'go' ready (272 MiB). On PATH in every run.
$ winquick run -w . -a app.exe -- go build -o app.exe .
→ ./winquick-artifacts/app.exe (PE32+ Aarch64)
Run a real Windows tool, get its output
$ winquick run -- pwsh -NoProfile -Command "$PSVersionTable.OS"
Microsoft Windows 10.0.26100
Drive a desktop app, capture a screenshot
$ winquick ui-test MyApp.csproj --script smoke.uitest
click SaveButton → get StatusText = "Saved"

Install

Install on macOS.

  • An Apple Silicon Mac (M1 or newer), macOS 13 (Ventura) or later
  • QEMU 11 or newer — Homebrew installs it for you
  • About 8 GiB of free disk for the Windows runtime and tools
  • Microsoft's Validation OS image (~2.4 GB), downloaded once by winquick setup under Microsoft's licence
  • Not inside a nested virtual machine — WinQuick needs real hardware virtualisation
Supported host

macOS · Apple Silicon

Homebrew installs WinQuick and its host dependencies.

brew install carlbomsdata/tap/winquick
Future plan

Windows & Linux

WinQuick runs only on macOS with Apple Silicon today. WHPX and KVM host code paths exist in the repository, but neither is supported or released yet. Watch the repository for progress.

WinQuick is open source under Apache-2.0. It runs locally, requires no account and sends no telemetry. It is intended for development and testing, not as a hardened malware sandbox.
