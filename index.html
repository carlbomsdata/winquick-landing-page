Instant disposable Windows environments.

Run Windows software from macOS without maintaining a Windows VM.

Use WinQuick for commands, builds, tests, desktop sessions and Windows-only tools. Each run starts clean, returns output and requested artifacts, then discards its writable state.

What you can do

A local Windows target for commands, builds, tests and desktops.

Run Windows software

Run Windows commands, .exe tools, closed-source and vendor utilities, and PowerShell. stdout, stderr and the exit code are returned unchanged.

winquick run -- pwsh -File .\build.ps1

Build and test projects

Copy a workspace into Windows, build or test, and copy back only the artifacts you name. Modern .NET and .NET Framework, including legacy targets, with packages restored offline.

winquick build ./MyApp -c Release

Bring your own tools

Register a Windows toolchain once as a cached volume. Every later run has it on PATH without re-copying it. Verified with Go, Node, Python, Zig and a C compiler.

winquick tool add go --from ./go

Automate desktop applications

Launch a desktop application that runs on Validation OS, capture screenshots, and drive the controls it exposes through Microsoft UI Automation. WPF and WinForms are verified end to end.

winquick ui-test MyApp.csproj --script smoke.uitest

Give agents a Windows runtime

A native MCP server exposes the run, desktop and UI-automation tools over stdio, for Claude, Cursor or any MCP client.

claude mcp add winquick -- winquick mcp

Disposable and offline

Each run discards its writable state; the base image and caches persist. The guest starts with no network device, and only requested artifacts are copied out.

winquick run -w . -a "bin/**" -- dotnet publish -c Release

When to use it

Built for scripted Windows work.

A traditional VM remains the right tool for interactive Windows use. WinQuick is for command-driven workflows: run a task, collect its output, and return to a clean state.

Traditional VM

  • Best for interactive Windows sessions
  • State persists unless you manage snapshots
  • File handoff and cleanup are your responsibility
  • Usually kept running for repeated tasks

WinQuick

  • Command-driven by default
  • Each run starts from a prepared clean state
  • Workspace copied in, requested artifacts copied out
  • Writable run state discarded afterwards
  • Scriptable from a shell, CI and agents

→ app.exe copied to ./winquick-artifacts

→ steps executed against exposed UI Automation controls
→ screenshots written to ./shots

$ claude mcp add winquick -- winquick mcp

Run a build step in a script

stdout, stderr and the exit code are preserved, so shell and CI logic behave as they would on Windows.

Performance

Measured warm-run performance.

After setup, WinQuick resumes a prepared Windows state for each run. These figures were measured on Apple Silicon M4 Pro, macOS 26, using a warm prepared guest. The first winquick setup downloads and prepares the runtime once and is not included.

~310 msclean Windows, cmd /c ver
~520 msdotnet --version
~690 msPowerShell 7 start-up
~340 msdesktop session start
~2.9 sgo build to a Windows .exe
~0.7 sprettier formats a JS file

100 runs of cmd /c ver gave p99 319 ms with zero failures. go build and prettier ran offline through tool volumes. Apple Silicon is the supported host; Windows and Linux are a future plan.

Desktop applications

Run and test Windows desktop applications.

The desktop capability starts a headless Windows desktop. Applications that run on Validation OS can be launched and screenshotted; those that expose Microsoft UI Automation can also be inspected and driven by control rather than by pixel. WPF and WinForms are verified end to end — built inside Windows, then driven. An application with no useful automation surface can still be captured, but not driven.

Install

Install on macOS.

  • An Apple Silicon Mac (M1 or newer), macOS 13 (Ventura) or later
  • QEMU 11 or newer — Homebrew installs it for you
  • About 8 GiB of free disk for the Windows runtime and tools
  • Microsoft's Validation OS image (~2.4 GB), downloaded once by winquick setup under Microsoft's licence
  • Not inside a nested virtual machine — WinQuick needs hardware virtualisation
Supported host

macOS · Apple Silicon

Homebrew is the supported install path. It pulls in QEMU and hivex and is not quarantined by Gatekeeper. A direct archive download is also available, but is unsigned until notarized.

brew install carlbomsdata/tap/winquick
Future plan

Windows & Linux

WinQuick runs on macOS with Apple Silicon today. WHPX and KVM host code paths exist in the repository, but neither is supported or released yet.

Scope

Supported scope and boundaries.

  • macOS Apple Silicon — the supported host. Windows and Linux host paths exist in the source but are a future plan.
  • Minimal guest — the guest is Microsoft Validation OS. Tools that require a Windows service it does not include will not run.
  • Desktop automation — controls are driven through UI Automation. Applications without a useful automation surface can be launched and captured, but not driven.
  • Install path — Homebrew is supported today. A direct archive is unsigned until Developer ID notarization is in place.
  • Boundary — WinQuick provides a hardware-VM boundary for your own builds and tools. It is not an audited malware sandbox.
  • Local only — no account, no telemetry, and no background daemon.
